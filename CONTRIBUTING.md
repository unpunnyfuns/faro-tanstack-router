# Contributing

## Development

```bash
npm install
npm test
npm run lint
npm run typecheck
npm run build
npm run check:exports
```

`check:exports` runs [publint](https://publint.dev/) and
[@arethetypeswrong/cli](https://arethetypeswrong.github.io/) against a packed tarball, so a
broken `exports` map or a mismatched `.d.mts`/`.d.cts` pairing fails in CI rather than after
publishing. Run `npm run build` first — it inspects `dist`.

## Releases

Releases are automated with [semantic-release](https://semantic-release.gitbook.io/). Merging
to `main` runs `.github/workflows/release.yml`: it determines the next version from the commit
messages, publishes to npm, cuts a GitHub release, and updates `CHANGELOG.md`.

Commit messages must follow [Conventional Commits](https://www.conventionalcommits.org/).
`fix:` cuts a patch, `feat:` a minor, and a `BREAKING CHANGE:` footer a major. Other prefixes
such as `chore:` or `docs:` release nothing.

✅ `feat: report not-found route matches`

❌ `added not found support`

`main` is protected. Work on a branch and open a pull request; CI must pass before merging.

Publishing uses [npm trusted publishing](https://docs.npmjs.com/trusted-publishers) over OIDC,
so no npm token is stored in the repository, and every published version carries a signed
provenance statement linking it to the commit and workflow run that built it.

`src/version.ts` is generated by `scripts/sync-version.mjs` during the release, from the
version semantic-release writes into `package.json`. Do not edit it by hand.

## Design notes

### Why setup needs two separate calls

`withFaroRouterInstrumentation` cannot reach Faro's `api` on its own. Faro hands that to an
instrumentation only after `initializeFaro()` runs, so registering
`TanStackRouterInstrumentation` is what supplies it. This mirrors how `@grafana/faro-react`
sets up its data router.

Passing the router into the instrumentation config instead would not work for TanStack Start,
whose convention is an exported `getRouter()` factory the framework calls per request. No
router instance exists at `initializeFaro()` time, so a config-only API would mean two
different setup stories for SPA and SSR. Wrapping the router keeps them identical.

The two calls are order-independent.

### How the navigation type is determined

TanStack does not carry the history action on its router events. It is recovered from
`__TSR_index`, which `@tanstack/history` writes into location state positionally: `push`
stores `currentIndex + 1`, `replace` stores `currentIndex` unchanged. Comparing the index on
`fromLocation` and `toLocation` yields the action with no extra subscription. A delta of `0`
is a replace; anything else is a push, back, or forward.

Redirects survive this filter even though TanStack applies `throw redirect(...)` as a replace,
because `resolvedLocation` only advances once a navigation settles. A push that redirects
therefore reports a single delta and collapses into one `route_change` on the final route.

### Structural router types

`src/types.ts` declares the parts of the router this package reads, rather than importing
types from `@tanstack/router-core`. That keeps TanStack's type-level churn from breaking the
build.

`src/integration.test.ts` is what verifies those structural types still match a real router.
If TanStack changes shape, that test is where it surfaces — the rest of the suite runs against
a fake router and would not notice.

### Module layout

| File | Responsibility |
| --- | --- |
| `types.ts` | Structural router shapes and config types |
| `dependencies.ts` | Module-level Faro `api`, `internalLogger` and options |
| `navigation.ts` | Push/replace detection from the history index |
| `routeChange.ts` | Builds and pushes `route_change` |
| `routeErrors.ts` | Scans matches for failures, deduplicates, reports |
| `instrumentation.ts` | The `BaseInstrumentation` subclass |
| `withFaroRouterInstrumentation.ts` | Subscription and SSR guard |

`routeChange.ts` and `routeErrors.ts` are pure functions over a router state snapshot, which
is why most of the suite needs only a fake router exposing `subscribe`, `state` and
`isServer`.
